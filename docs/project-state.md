## Task line in the chat flow (2026-10-21, v1.13.36+69, dev fcb5ec7, Dev CI 39622108793 green (analyze, tests, APK build))
Owner: the thinking/working line sat over the keyboard (docked above the composer); it should be on SubMac's side, in the chat, under your message, like ChatGPT / Hark / Kimi. Not tested on a real phone.
- **Why it looked docked**: the line was item 0 of the reversed message list, so it was always the bottom-most thing on screen, pinned against the composer, with the reply growing above it.
- **Now** (`home_screen.dart` `_MessageList`, `composer.dart` `WorkingLine`, `message_view.dart` `WorkSummary`): the newest turn (your message + everything SubMac said since, or the replies after a bot wake) is one block at the bottom of the list. The line sits at the top of SubMac's reply, right under your message, and scrolls with the chat. A turn you send from this screen gets the screen to itself (`minHeight` = viewport): your message at the top, the reply growing under it; older turns and opened chats take only their own height. Main chat and bot chats (same screen).
- **Hand-over without a jump**: a plain reply with no step takes the line's place once it has streamed for 1.2 s (`WorkingLine.handOver`, so a task's first line followed by its first step never blinks); a task keeps the line and at the end it turns into "Worked for 1m 12s · 5 steps" in the same spot (`WorkSummary(head: true)`: same 30 px row, same edge, a tick in the mark's place; the fold no longer sits over the final answer for the current turn). Older turns keep the fold over their answer.
- Kept: tap the line for the step list (ticks, "didn't work", seconds per step, browser checklist), elapsed time, Watch/Hide for browser tasks, "N more" when several tasks run here, status wording (Still thinking / Taking a little longer).
- **Stop** moved to the composer: the send button is Stop (ink circle, paper square) while SubMac works here and nothing is typed; typing turns it back into Send to steer; on the resting bar the Live pill becomes Stop. Stops every task in this chat (`stopRun`).

## Model proxy speed: Supabase vs Cloudflare (investigation 2026-10-21; acted on in "Proxy speed pass" above)
Question from the owner: would moving `ai-chat` to Cloudflare Workers make the app faster? The resume proxy on submac.site (Cloudflare Pages Functions) feels faster.
- **Measured** (temporary user, deleted after; sandbox in Oregon, so absolute network numbers differ from Somalia; Server-Timing is measured inside the function):
  - Supabase runs the function in the region nearest the caller unless the request pins it (`x-region` header or `forceFunctionRegion`; docs: https://supabase.com/docs/guides/functions/regional-invocation; there is no Africa or Middle East region). Unpinned from Oregon it ran in us-west-2 and every DB call crossed to Frankfurt: cfg 700-780 ms + checks 550-600 ms = **~1.3 s before the model is called**; total server time 1.84-1.96 s for a tiny submac-fast reply. Pinned to eu-central-1: cfg 130-240 ms + checks 155-190 ms = **~0.3-0.4 s**, server total 0.76-1.18 s.
  - `/status` (no model): unpinned server 0.86-1.37 s, pinned 0.24-0.28 s. Cloudflare comparison: submac.site `/api/ai-status` answered in 74-78 ms warm (cfWorker 32-35 ms).
  - The in-isolate caches (`config()` 60 s, `capOf` 30 s) never hit: every request was a fresh isolate (cfg never under 100 ms). Same finding as the 1.13.32 timing work.
  - Upstream first byte (from Frankfurt): submac-fast (Ollama Cloud gpt-oss:20b) 450-780 ms tiny prompt, 560-580 ms with a 7k-token prompt; submac-smart (NVIDIA NIM nemotron-3-ultra-550b) 0.6-3.2 s.
  - Real traffic, last 7 days (`ai_usage`, ttft from the first upstream try incl. fallbacks): submac-smart NVIDIA p50 1.5 s / p90 5.0 s (p50 prompt 13k tokens), Gemini p50 4.4 s / p90 11.4 s, Dahl p50 13.2 s (2.3 tries avg); submac-fast Ollama p50 0.7 s / p90 1.3 s. 416 failed upstream tries vs 1,151 successful in 7 days (each failure is a fallback delay).
- **What each proxy does before the first upstream byte**:
  - ai-chat: gateway JWT check -> isolate boot (imports npm:@supabase/supabase-js) -> `ai_get_config()` RPC (38 KB, decrypts every key for every route; 32 ms in the DB, 110-240 ms from the function in-region) -> 4 parallel queries (blocked, 60 s request count, today's usage, `ai_user_cap`) -> route/fit logic -> upstream fetch -> waits for the first upstream chunk -> streams. Usage is recorded after the stream (`waitUntil`), already off the critical path.
  - submac.site tailor: `getUser` (Auth API) -> 4 rate-limit RPCs one after another -> `consume_credit` RPC (all to its us-east-1 DB) -> keys from env (no DB) -> Gemini flash-lite `generateContent` direct, non-streaming JSON. It does not do less DB work; it feels fast because the Worker runs at the edge, keys/config are in env, and the model is a small Gemini model with a short prompt. Different job (one JSON call), not a chat with 7-13k-token prompts and tools.
- **Verdict**: Moving to Cloudflare would not by itself make answers much faster. The proxy costs ~0.3-0.4 s when it runs next to the DB and ~1.3 s when it runs far from it; the model/provider costs 0.5-5 s typical (up to 13 s on slow routes) plus fallbacks. A Worker near Somalia would still need the same DB round trips to Frankfurt (each one longer than now), unless config/keys move to Worker env/KV and the allowance moves to a KV/Durable Object, which is a rewrite of quota enforcement.
- **Cheaper fixes, in order** (not deployed: the live `ai-chat` is version 29, deployed 2026-10-20 15:29 UTC, but dev's source was last changed at v21 on 2026-10-19, so the live code is not in the repo; redeploying dev's source could undo the owner's later changes):
  1. Pin the region from the app: send `x-region: eu-central-1` on every proxy call (`lib/services/cloud.dart` / `llm_client.dart`). Saves ~1 s per call whenever the user is routed to a non-Frankfurt region. Check `x-sb-edge-region` from a phone in Somalia first; log it (or record `SB_REGION` in `ai_usage`) to know where Somali traffic runs now. Trade-off: no automatic reroute during a Frankfurt outage (the DB is there anyway).
  2. One RPC instead of five: `ai_chat_gate(uid)` returning settings + aliases/routes + blocked + 60 s count + today's usage + cap in one round trip (keep the same checks and order). Expected ~150-250 ms saved in-region.
  3. Start the upstream call in parallel with the checks (abort it if a check fails; never send a byte to the app before the checks pass). Saves the checks time (~150-200 ms) at the cost of a wasted provider call for blocked/over-limit users; do after 2.
  4. Config without decrypting all keys (decrypt only the chosen route's keys), and drop the supabase-js import for plain PostgREST fetches to shorten cold boot.
  5. Biggest win overall is the model side: put a fast, reliable route first for submac-smart (Gemini routes are marked unhealthy and fall through; Dahl averages 2.3 tries), keep prompts small, and use submac-fast for short turns (already done in the app).

## Voice calls: long answers (2026-10-19, v1.13.29+62, dev 3f6e1a6, Dev CI 39296990832 green)
