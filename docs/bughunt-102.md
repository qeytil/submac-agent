# Deep bug hunt fixes (v1.13.102+172)

The deep bug hunt on build-61 found 13 bugs. This file says how each one was fixed. The regression tests are in `test/bughunt_fixes_test.dart`. Every test there started as a probe that passed by showing the bug; each now checks the fixed behaviour.

| # | Bug | Fix |
|---|-----|-----|
| C1 | A connector call given an absolute URL sent the app's auth headers to any host. A GET counted as a read, so no approval was asked. | `_call` refuses any absolute URL that is not https on the connector's own base host, and also checks the final host after the path is joined. `api_call` with `connector` goes through the same check. `isRead` is false for any off-host URL. |
| H1 | `isRead` read the whole path including the query, its search/query matches were not anchored, and any GET was a read. | `isRead` looks only at the path (`pathOnly`) and anchors `search`/`query`/`graphql`/`databases/x/query`. Telegram reads only through an allow-list (`telegramReads`), so `send*`, `delete*` and the rest always ask. Slack reads only for list/history/info…, never `chat.postMessage`. `ConnectorTools.isWrite` is anchored too. |
| H2 | An error message carried the Telegram bot-token URL into the chat, the backup and the model. | `ConnectorCatalog.execute` and `test` scrub every saved connector secret, URL-encoded forms included. A new core hook, `CoreHooks.cleanOutput`, runs `ToolOutputClean.clean` (connector secrets, then `AiKeys.redact`) on every tool result, in the main, team and browser runs, before it is journaled, saved or sent. |
| H3 | `app_settings` changes had no approval. | `AgentTools.settingsRisk` asks before changing approval_mode, actions_enabled, about_you, how_to_respond, memory, wake_word, wake_screen_off or wake_sensitivity. The router sets kind `settings` (`FullAccess.alwaysAskKind`). That kind always asks, with Full access, a Trusted level and a trusted team included, never offers "Allow always", and is never released when Full access turns on (`Approval.alwaysAsks`). |
| H4 | On resume, only calls made after the newest user message were settled, so a message typed mid-task hid a side-effect call that had been cut off. | The journal header stores `from`, the id of the user message that started the run. `ResumeSettle.unanswered(list, fromId:, journalIds:)` settles every unanswered call from that point, plus any call the journal saw start or wait. |
| H5 | Error retries were counted for the whole run, a steer counted as a failure, and the raw word "steered" was shown. | The count resets whenever a step comes back (`maxFailuresInRow` = 8 in a row). Steers are counted separately, with a ceiling of 100 so a stuck flag can't loop. A run that does end on a steer shows `AgentCore.steerStopText`, never "steered". |
| M1 | Replies without tool calls were never counted, which threw off bot budgets and Bot Activity. | A new `CoreHooks.usage(Reply)` runs for every model call, including replies a finish gate sends back. Main hooks count tracer tokens and the task's own size there. The after-guards now only decide whether to take tools away. |
| M2 | A checkpoint was due only when `step % segment == 0`, so it was skipped when a finish gate pushed the step past that number. | `CheckpointClock` fires when the step is a full segment or more past the last checkpoint. The checkpoint note follows the guard, and the office budget note is given once, at or after the cap. |
| M3 | A resumed background job (bot wake or team job) lost its background limits. | The journal header records `background`/`office`/`jobKind`. **Background runs are not resumed.** Their limits (background lane, office step cap, spend stop) and the job around them (team task status, the bot's report) lived only in the process that died, and restoring the maps without that job would leave them set forever. Their cut-off calls are still settled in the chat, a send or payment marked "unknown, check first", and the journal is marked `skipped_background`. A routine runs again at its next time; a team task waits for the owner or the lead. |
| M4 | Strings that already had translations showed in English. | The 78 literals that already had translations, plus 7 more covered by the new keys, are wrapped in `tr()`. 6 missing keys were added (Copy, Copied, Reply, Select text, Skills, `Pay {usd}`), plus the banner sentences. Banners take `{holes}` (`setBanner(text, args)`, `bannerArgs`), so "Paused after {n} steps…" and "Task finished in "{chat}"." translate. A guard test fails on any new unwrapped `Text('…')` literal that has a Somali and Arabic translation. |
| L1 | The team step cap showed an empty snackbar. | The cap's halt reason is now `AppState.officeCapReason`, a real sentence. An empty banner is never shown. |
| L2 | Stopping a team did not cancel the call or tool in flight. | `TeamRun` keeps each team's `AgentCore`s, and "stop" calls `core.stop()` on all of them (`stopWork`). `AgentCore` now races the transport and any running tool against stop, because Genkit's own cancel does not interrupt a call already running. |
| L3 | There was no lint configuration, and the analyzer showed real warnings. | `analysis_options.yaml` now uses flutter_lints, plus cancel_subscriptions and use_build_context_synchronously. Fixed: browser_jobs protected `notifyListeners` (now `changed()`), life_tools return-await in try, offices_screen context after await, 7 unused imports, unnecessary `!`, dead code, `catchError` return. Pure style rules are switched off with reasons in the file. App-lifetime subscriptions are ignored with a reason. `flutter analyze`: 0 issues. |
